## Copy `examples/` whole — and why the earlier prune was wrong

An earlier version of this file listed 11 of the 25 `examples/` as droppable,
on the ground that 0 of 1267 `coqdep` edges from any retained file reaches
them.  That is true and it is the wrong criterion.  An example is a LEAF by
construction -- nothing ever `Require`s it -- so reachability does not select
for redundant evidence, it selects for "not imported by `eval/Extract.v`".
For a proof artifact the examples ARE the claims, which is the one place where
unreachable and unnecessary come apart.

Checked against the 11: **8 of them are load-bearing.**

  * `Ex_PrimaryKey.v` is the only witness anywhere for `DRow` and `DCheck` --
    two of the four `decl` constructors, and the pair that illustrates the
    classification principle `constraint/Decl.v` argues for (a class exists
    for what a rewrite can exploit; `DRow`'s cheap guard tests one row where
    `DCheck`'s must scan the table).
  * `Ex_SnocMaintenance.v` is the only witness for `WSnoc` and for append
    maintenance -- `tbl := tbl ++ [row]` maintained for all eight index
    kinds, with the append and the cons pinned to the same write.  That is
    the answer to "isn't cons-only a modelling bias?".
  * Six are cross-referenced from RETAINED prose, 9 references in all:
    `Ex_TrigramSimilarity` (4, including `pipeline/Selector.v:251`, which
    cites it as the deliberate expressibility witness for a hand-rolled
    trigram extraction the detector does not catch -- a stated LIMITATION
    whose evidence the prune deleted while leaving the prose),
    `Ex_Join` (`rules/SplitFilterProj.v:32`), `Ex_DictMinKey`
    (`index/CompositeDictIndexImpl.v:69`), `Ex_BFS` and `Ex_Family`
    (`eval/SelectorTests.v:478`), `Ex_UniqueIndexPipeline`
    (`eval/HA_LookinFunctions.v:73`).

Only `Ex_PrimaryKeyIndex`, `Ex_UniqueIndex` and `Ex_UniqueIndexInstall` came
out clean, and they are 667 lines.  The whole `examples/` folder is 6,059
lines, ~11% of the Rocq source, so pruning it buys little and costs claims.

`src/fiat2/TrigramSimilarity.v` (108 lines) stays with it: it is required by
`Ex_TrigramSimilarity`.

### Which `examples/` files carry what

Six `Ex_*` files are **measured subjects**, not tests, and `eval/Extract.v`
lists them in the same `subjects` table as `keycloak` and `area_registry`:

```
Ex_RangeDelete  Ex_MinDelete  Ex_CompositeKey  Ex_CompositeKeyDecl
Ex_CompositeKeyedDelete  Ex_KeyedDictTwoDeletes
```

They produce **8 of the 23 rows** in every results table, because they are the
subjects where the corpus had no witness for the rule being priced. `min_delete`
carries the headline enumerate-and-measure finding — the one subject where the
selector's pick loses at all three storage settings. Dropping these deletes a
third of the evaluation.

`Ex_Triangle.v` also stays: it carries the join claim and is the only
`examples/` file that uses `Selector`.

The seven textbook examples (`Ex_Employee` `Ex_FlagFilter` `Ex_Inventory`
`Ex_Orders` `Ex_Range` `Ex_Sum` `Ex_SumDelete`) are reachable only from
`eval/SelectorTests.v` and produce no measured row. They are the only files
that show a rule on a program small enough to read in one screen, so they
stay too.

## Do not copy

- `haskellServer/` — not part of this development.
- Build output: `*.vo *.vok *.vos *.glob *.aux .lia.cache`,
  `Makefile.coq* _CoqProject .Makefile.coq.d .coqdeps.d`, `harness/_build/`,
  `harness/generated/extracted.ml{,i}` (regenerated by the build).

### Two copying pitfalls, both of which cost a failed build once

1. `rsync --exclude='Makefile.coq*'` does **not** match the dot-prefixed
   `.Makefile.coq.d`. A stale one carries absolute paths back into the source
   tree and the copy fails with "Unable to locate library fiat2.Language".
2. Excluding `generated` drops `harness/generated/dune`, after which the
   extraction lands in a directory with no library declaration and the harness
   fails with `Library "conquord_extracted" not found`. Ship the `dune`, not
   the extracted `.ml`.

A recipe that works:

```sh
rsync -a --exclude='_build' --exclude='*.vo' --exclude='*.vok' --exclude='*.vos' \
         --exclude='*.glob' --exclude='*.aux' --exclude='.lia.cache' \
         --exclude='Makefile.coq*' --exclude='.Makefile*' --exclude='.coqdeps.d' \
         --exclude='_CoqProject' --exclude='generated/extracted.*' \
         <src>/fiat2/ <dst>/fiat2/
```

## Checks the copy should pass

| check | expected |
|---|---|
| `make -j12` from a clean tree | exit 0, and `grep -c '^Error:'` on the log is 0 |
| holes | `grep -rnE 'admit\.|Admitted|^Axiom|^Parameter' src/fiat2` finds none |
| orphaned `.vo` | none — every `.vo` has a `.v` beside it |
| extraction | `harness/generated/extracted.ml` is **1,242,053 bytes** |
| harness | `cd harness && dune build` exit 0, 23 subjects, `UNANNOTATED=0`, 0 unsupported |
| differential | `dune exec -- ./main.exe check share=8` → 1230 configurations, 0 mismatches |
| results reproduce | `./reproduce.sh` regenerates `harness/results/`; the six counted files are byte-stable |

Judge a build by its **exit code**, not by the `.vo` count: a file that fails
to compile keeps its previous `.vo`, so the count still reads full.
